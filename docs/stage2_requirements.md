# Project Requirements Document

## Smart Energy Smart-Meter Pulse Counter & Analytics Agent

**Domain:** IoT, Embedded & Virtual Sensors  
**Programming Language:** C++  
**Operating System:** Linux  
**Project Type:** Individual Project

---

## 1. Introduction

The Smart Energy Smart-Meter Pulse Counter & Analytics Agent is a Linux-based C++ project designed to process pulse data generated by a smart energy meter.

Smart meters can generate electrical pulses corresponding to energy consumption. The project simulates this process in software and provides functionality to count pulses, process energy readings, store readings, and perform basic analytics.

The project demonstrates concepts related to IoT, embedded systems, Linux, C++, hardware and software interaction, system programming, data structures, and software testing.

---

## 2. Problem Statement

Smart-meter systems generate raw pulse information that needs to be processed to obtain meaningful energy-consumption data.

The objective of this project is to develop a software-based system that can process smart-meter pulse inputs, maintain a pulse count, generate energy readings, store those readings, and calculate basic energy statistics.

The initial system will use a virtual/simulated pulse source instead of requiring physical smart-meter hardware.

---

## 3. Objectives

The project objectives are:

- Develop a smart-meter pulse counting system using C++.
- Run and test the application in a Linux environment.
- Process virtual smart-meter pulse inputs.
- Maintain an accurate pulse count.
- Generate and store energy readings.
- Calculate total energy consumption from stored readings.
- Calculate average energy readings.
- Develop modular and reusable C++ components.
- Implement unit tests for major components.
- Use Git and GitHub for version control.
- Demonstrate hardware and software interaction concepts.
- Follow a structured software development process.

## 5. Functional Requirements

### FR-01: Pulse Input

The system shall accept simulated pulse inputs representing energy consumption events.

### FR-02: Pulse Counting

The system shall maintain a count of the pulses received from the pulse source.

### FR-03: Pulse Count Retrieval

The system shall provide the current pulse count when requested.

### FR-04: Energy Processing

The system shall process pulse information to represent energy consumption readings.

### FR-05: Energy Reading Storage

The system shall store generated energy readings for further processing.

### FR-06: Add Energy Reading

The analytics module shall allow new energy readings to be added to the collection.

### FR-07: Total Energy Calculation

The system shall calculate the total energy represented by the stored readings.

### FR-08: Average Energy Calculation

The system shall calculate the average value of the stored energy readings.

### FR-09: Data Logging

The system shall provide functionality for recording relevant meter and energy information.

### FR-10: Input Validation

The system shall handle invalid input values appropriately.

### FR-11: Testing

The major modules shall have tests to verify their expected behaviour.

### FR-12: Modular Architecture

The system shall separate major functions into independent modules.

---

## 6. Non-Functional Requirements
